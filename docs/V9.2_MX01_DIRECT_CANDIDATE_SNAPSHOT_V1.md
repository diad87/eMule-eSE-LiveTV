# MX01 — `DirectCandidateSnapshotV1`

Status: frozen documentation contract for v9.2 (`TH92-1`). This document,
the JSON Schema and its goldens are normative. They define the sanitized,
non-actionable diagnostic projection of a logical local candidate contract;
they do not add product code, a network message or a binary ABI.

Normative words `MUST`, `MUST NOT`, `SHOULD` and `MAY` have their usual
RFC 2119 meaning.

## 1. Boundary and purpose

`DirectCandidateSnapshotV1` lets an API, UI, test or exported diagnostic
distinguish an observed candidate from a verified candidate without reading
product logs or constructing a native mapper. It is an observation contract,
not a route selector. It carries no raw endpoint and MUST NOT be accepted as
input to publication, connection or route-selection decisions.

The strict producer form is
[`reachability/direct_candidate_snapshot_v1.schema.json`](reachability/direct_candidate_snapshot_v1.schema.json).
Every domain object is closed. A producer MUST reject missing, unknown or
ill-typed fields before publication and MUST fail closed when it cannot prove
one of the frozen enum values.

The top-level fields are:

| Field | Meaning |
|---|---|
| `schema_version` | Exactly `1`. |
| `topology_generation` | Current non-zero monotonic topology generation, limited to the JavaScript safe-integer maximum `9007199254740991`. |
| `created_at_monotonic` | Process-monotonic millisecond observation time, limited to `9007199254740991`; never civil time. |
| `candidates` | At most 16 sanitized `DirectCandidateV1` objects. |
| `terminal_reason` | `NONE` whenever `candidates` is non-empty; otherwise a stable non-`NONE` reason for the empty local snapshot. It makes no claim that a remote peer is universally unreachable. |

All JSON integers in the logical `uint64` generation/time positions are
restricted to the ECMAScript safe-integer range. A producer MUST stop
publishing V1 and return a typed overflow/malformed result before either value
would exceed `9007199254740991`; it MUST NOT round, wrap or stringify only one
occurrence. Candidate generations use the same bound.

`lease_expires_at` deliberately contains a snapshot-relative
`remaining_ms`, not a wall-clock timestamp. A persisted observer reconstructs
its own local deadline from the observation time. A `null` value means that
there is no finite lease deadline, not that the candidate is verified.
For `MAPPED_V4`, a finite value of zero MUST be `EXPIRED` and MUST NOT be
emitted as `CANDIDATE`, `VERIFIED` or `STALE`. A verified finite mapping
therefore requires `remaining_ms > 0`; a verified permanent mapping uses
`null`.
Retained `EXPIRED` or `STALE` records still make the array non-empty, so their
cause appears in candidate `reason_code` while top-level `terminal_reason`
remains `NONE`.

## 2. Frozen enums

These values are closed for schema version 1. They are case-sensitive.

| Enum | V1 values |
|---|---|
| `kind` | `HOST_V6`, `DIRECT_V4`, `MAPPED_V4`, `LAN` |
| `source` | `OS`, `STATIC`, `UPNP_IGD`, `PCP`, `NAT_PMP` |
| `scope` | `GLOBAL`, `SAME_LAN` |
| `verification_state` | `CANDIDATE`, `VERIFIED`, `EXPIRED`, `STALE` |
| `reason_code`, `terminal_reason` | `NONE`, `DISABLED_BY_PREFERENCE`, `NO_LISTENER`, `NO_ROUTE`, `NO_GATEWAY`, `NO_MAPPING_PROTOCOL`, `OPERATOR_DENIED`, `MAPPING_DENIED`, `MAPPING_CONFLICT`, `MAPPING_TIMEOUT`, `INVALID_RESPONSE`, `STALE_GENERATION`, `LEASE_EXPIRED`, `INTERFACE_CHANGED`, `ENDPOINT_DEPENDENT_MAPPING`, `INBOUND_FILTERED`, `SERVER_CALLBACK_FAILED`, `PEER_INCOMPATIBLE`, `PORT_IN_USE`, `VERIFICATION_TIMEOUT`, `CGNAT_WITHOUT_LEASE`, `ROUTER_REJECTED_ALL_CANDIDATES` |
| `transport` | `TCP`, `UDP` |
| `network_kind` | `NATIVE`, `OVERLAY`, `UNKNOWN` |
| `ownership_state` | `NOT_APPLICABLE`, `OWNED_BY_US`, `FOREIGN`, `UNVERIFIABLE`, `UNKNOWN` |

The reason names are the stable uppercase projection of
`natmap::ReasonCode`; they retain the public type's existing numeric order but
the JSON never exposes or relies on those numbers.

Unknown rules are fail-closed:

1. A V1 producer MUST NOT emit an unknown enum.
2. A V1 consumer MUST treat any candidate containing an unknown enum as
   non-actionable. It MUST NOT map an unknown value to the nearest known value.
3. An unknown top-level reason makes the whole terminal interpretation
   unsupported.
4. An unsupported `schema_version` MUST return a typed unsupported result, not
   attempt best-effort promotion.
5. `network_kind = UNKNOWN` and `network_kind = OVERLAY` never prove native
   connectivity, regardless of address class. A `HOST_V6`, `DIRECT_V4` or
   `MAPPED_V4` candidate with either origin MUST NOT be emitted as `VERIFIED`.
   RFC 6598 is not native CGNAT evidence when the network origin is not
   `NATIVE`.

## 3. Candidate, verified, expired and stale

The four verification values are intentionally not aliases:

- `CANDIDATE` means a structurally valid, generation-bound local observation
  exists, but the route-specific positive predicate is incomplete.
  `verification_attempt_id` and `evidence_digest` MUST be `null`.
- `VERIFIED` means the producer already validated the exact endpoint,
  transport, attempt, generation and evidence within the allowed monotonic
  window. Both redacted digests MUST be present. A mapper success, a lease, an
  address class, a high ID by itself, or a state name by itself is
  insufficient. A finite mapped lease at zero is never verified.
- `EXPIRED` means the current-generation finite lease reached zero.
  `reason_code` MUST be `LEASE_EXPIRED`, and verification evidence is
  withdrawn. Conversely, a mapped candidate exposing a finite zero remaining
  lifetime MUST be represented only as `EXPIRED`.
- `STALE` means the candidate belongs to an older topology generation.
  `reason_code` MUST be `STALE_GENERATION`, and verification evidence is
  withdrawn.

For classic eD2K TCP, `VERIFIED` requires both server high-ID evidence and an
inbound accept for the exact same endpoint, attempt, generation and time
window. For IPv6, it requires positive inbound evidence or a verified pinhole
bound to the exact internal endpoint, interface and generation. `LAN` is
`SAME_LAN` only after positive evidence for the same local reachability
domain. Overlay evidence cannot promote `HOST_V6`, `DIRECT_V4` or
`MAPPED_V4` as native reachability.

The producer MUST keep `candidate_id` stable only while kind, transport,
socket endpoint identities, interface identity, mapping identity and topology
generation remain unchanged. Any one of those changes yields a new ID. A
stale record retains the ID of the old generation it describes; it cannot be
reused for a new-generation candidate. Stability applies across snapshots
from the same producer session. A producer restart creates a new session key
and therefore new redacted IDs.

Within one snapshot, each `candidate_id` MUST occur exactly once. Repeating an
otherwise identical object is ambiguous and invalid. Reusing the same ID for
objects that differ in transport, endpoint identity, mapping identity,
interface identity, kind or generation is an identity collision and invalid.
The strict schema rejects exact duplicate objects; the semantic validator MUST
also reject duplicate IDs whose surrounding objects differ. Additive fields
MUST NOT weaken this snapshot-wide invariant.

The inverse is also mandatory: one logical identity MUST map to exactly one
`candidate_id` in a snapshot. Its frozen signature is exactly `kind`,
`transport`, both endpoint `identity_digest` values,
`interface_identity_digest`, `mapping_identity` and
`topology_generation`. Two different IDs with the same signature are
ambiguous and MUST fail closed. Classification, source, scope, ownership,
verification state, evidence and additive fields do not create a second
logical identity.

This JSON contract records state only. It does not choose between verified
routes or alter classic fallback. MX02 and any v9.3 handoff that needs an
actionable endpoint MUST consume a process-local, typed, non-serializable
internal view carrying the same logical candidate identity plus the real
`natmap::Endpoint` and exact evidence binding. That internal view is not this
JSON schema and MUST NOT be exported. Code MUST NOT attempt to reconstruct an
address, interface, transport-layer numeric port or endpoint from any digest
in this projection.

## 4. Field → producer → validator → redaction

All producer names below are existing public/state surfaces. The final
integration may be a mechanical projection, but it MUST preserve the
validators in this table.

| Snapshot field | Authoritative producer | Required validator | Exported representation |
|---|---|---|---|
| `schema_version` | MX01 constant | Exactly `1` | Integer |
| top-level `topology_generation` | `natmap::ReachabilitySnapshot::topology_generation` / `CDirectReachabilityManager::GetTopologyGeneration()` | Non-zero; one atomic snapshot; at most `9007199254740991` | JS-safe integer |
| `created_at_monotonic` | manager monotonic clock | Non-decreasing within a process; at most `9007199254740991` | JS-safe milliseconds; no wall clock |
| `candidates` | generation-bound projection of `PlaneSnapshot`, direct observations and scoped LAN evidence | Maximum 16; ID and frozen logical-identity signature form a snapshot-wide one-to-one relation; each candidate passes all rows below | Array |
| `terminal_reason` | stable `natmap::ReasonCode` projection | Exactly `NONE` for a non-empty array; known non-`NONE` enum for an empty array | Frozen name |
| `candidate_id` | kind + transport + raw endpoint identities + route binding + mapping identity + generation | Recomputed on any identity change | Domain-separated keyed digest |
| `kind` | plane/family plus admitted mapper or positive LAN scope | Known kind; no future-kind inference | Frozen name |
| `transport` | `natmap::Transport` | Known `Tcp`/`Udp` | `TCP`/`UDP` |
| `local_endpoint`, `published_endpoint` | `natmap::Endpoint` plus `ClassifyAddress` | `Endpoint::IsUsable`; both endpoints of `DIRECT_V4` are `IPV4/PUBLIC`; both endpoints of `HOST_V6` are `IPV6/GLOBAL`; mapped publication is `IPV4/PUBLIC`; exact numeric endpoint data remains internal | Family, coarse class and keyed identity digest only |
| `network_kind` | `ClassifyNetworkOrigin(RouteBindingIdentity evidence)` | Known `NetworkOrigin`; independent of address class | `NATIVE`/`OVERLAY`/`UNKNOWN` |
| `interface_identity_digest` | current `natmap::RouteBindingIdentity` | `ValidateRouteBinding`; family/address/origin and current generation match | Domain-separated keyed digest |
| `source` | OS/static observation or `natmap::MapperSource` + `MapperKind` | Known and coherent pair; `None` is not a candidate; PCP CPE/upstream both project to `PCP` | Frozen name |
| `scope` | address policy and positive `PrivateAddressScope` evidence | Non-LAN kinds are `GLOBAL`; `LAN` is positively proven `SAME_LAN` | Frozen name |
| `mapping_identity` | admitted internal ownership proof plus mapping topology identity | Required for `MAPPED_V4`; absent otherwise; mapper result current and structurally valid | Re-keyed domain-separated digest or `null` |
| `lease_expires_at` | `LeaseController::timing().expires_monotonic_ms` and capture time | Clamp subtraction at zero; permanent mapping is `null`; finite verified mapping is greater than zero; zero is exactly `EXPIRED` | `SNAPSHOT_RELATIVE` + `remaining_ms` |
| `ownership_state` | validated `MapperResultData::ownership` | `MAPPED_V4` candidates require `OwnedByUs`; non-mapped is `NOT_APPLICABLE` | Frozen state only |
| `verification_state` | `CandidateObservation`, `PlaneSnapshot`, `VerificationAttempt` and exact evidence predicate | Candidate is not verified; current generation; endpoint/transport/attempt/window match; expiration and staleness withdraw evidence | Frozen state |
| `verification_attempt_id` | `natmap::VerificationAttempt::attempt_id` plus its bound identity | `VerificationAttempt::IsValid` and exact current-generation binding | Domain-separated keyed digest or `null` |
| `evidence_digest` | exact `natmap::Evidence` set accepted by the route-specific verifier | `IsFreshFor` for every required item; exact endpoint/attempt/generation/window | Re-keyed domain-separated digest or `null` |
| `reason_code` | `natmap::ReasonCode` | Known enum and coherent with verification state | Frozen name |
| candidate `topology_generation` | captured plane/attempt/mapping generation | JS-safe; equal to snapshot generation except `STALE`, which is strictly older | Integer |

The schema validates shape, closed enums and same-object implications. The
producer's semantic validator additionally enforces cross-object generation,
candidate-ID stability, exact evidence correlation and endpoint equality;
JSON Schema cannot express those comparisons.

## 5. Redaction contract

Every `*-v1:<hex>` value MUST be HMAC-SHA-256 with one randomly generated,
non-exported producer-session key and a distinct domain label for candidate,
endpoint, interface, mapping, attempt and evidence identities. The key MUST
remain stable for the full producer session so unchanged logical identities
remain stable across snapshots, and MUST be regenerated on producer restart.
It MUST NOT rotate per export. A bare hash of a small address space is
forbidden. The key and raw input are never part of this snapshot.

This contract MUST NOT expose:

- a protocol nonce, ownership token or cleanup authorization material;
- an interface GUID, index, human-readable name or description;
- a complete address, gateway address or any other exportable IP literal;
- a raw TCP/UDP port number or any equivalent numeric endpoint locator;
- an internal pointer, object address or mutable product reference;
- raw evidence, raw protocol response, secret, credential or authentication
  material;
- free-form logs or text parsed from logs.

Only address family, coarse address class and keyed endpoint identity remain
in the endpoint projection. The real address and numeric port remain solely in
the process-local typed view. `evidence_digest` is only a local correlation
handle; it is not a portable proof and MUST NOT be treated as one.

## 6. Compatibility

The strict producer validates against the closed schema and emits no unknown
field. That is the canonical V1 form used by goldens.

A compatibility observer MAY project only the V1 fields and ignore benign
additive fields carrying no V1 semantics and no prohibited endpoint locator.
Before projection it MUST recursively inspect additive keys and values at
every depth. A normalized additive key containing a locator token such as
`ip`, `ipv4`, `ipv6`, `address`, `addr`, `port`, `endpoint`, `socket`,
`locator`, `gateway`, `host`, `interface`, `adapter` or `nic` is a privacy
failure. Compact role prefixes including `src`, `dst`, `wan`, `lan`, `nat`,
`public`, `private`, `local`, `remote`, `internal` and `external` are checked
against compact locator suffixes, so forms such as `srcip`, `dstport`,
`wanip`, `natport`, `ipaddr`, `hostaddr` and `hostport` cannot bypass token
splitting. Abbreviated roles `d`, `s`, `r`, `l`, `pub`, `ext`, `int` and
`sock` are subject to the same rule; `dport`, `sport`, `rport`, `lport`,
`pubip`, `pubport`, `extip`, `extport`, `intip`, `intport`, `sockaddr` and
`sockport` are therefore forbidden.

Additive keys denoting secret, authorization or raw material are equally
forbidden at every level. Sensitive tokens include `nonce`, `token`,
`pointer`, `secret`, `credential`, `password`, `auth`, `authorization`,
`attempt`, `cleanup`, `owner`, `ownership`, `raw` and `evidence`; this closes
fields such as `owner_token`, `protocol_nonce`, `ownership_nonce`,
`cleanup_token`, `object_pointer` and `raw_evidence`. Compact and camel-case
forms are subject to the same normalization.

Matching MUST remain token/role based: benign names including `future_note`,
`retry_count`, `counts`, `digest`, `enum` and `relationship_note` are not
locator or secret names.

The complete additive key string is also checked as a possible locator
literal, not only its normalized tokens. An IP literal, `host:port`, bracketed
IPv6 endpoint or network URL used as a key is forbidden even when its value is
benign. The same literal checks apply to every additive string value.
For exactly one `:` separator, any non-empty host prefix followed by a decimal
port suffix is rejected without attempting ASCII hostname validation. This
covers single-label names, IDNs, Unicode dot-like separators and an FQDN with
an optional trailing dot. This rule deliberately has no hostname-role
allowlist: `version:2`, `ticket:12345`, `12:34`, `ratio:1` and `chapter:7`
are syntactically ambiguous with a network endpoint and therefore are not
benign additions. Producers MUST represent those concepts as separate fields
or as text without a colon followed only by decimal digits. Bracketed IPv6
remains an explicit case. URLs and network-path references with an authority,
including `//host:port/path`, are parsed safely and rejected. Authority-plus-
path forms without a leading network-path marker, including
`198.51.100.1:4662/path` and `example.test:4662/path`, are parsed by adding
`//` solely for host/port validation and are also rejected. Such input MUST be
`MALFORMED`, not silently ignored. Valid Unicode text without locator syntax
remains compatible within the string budget.

IP literal detection normalizes common complete-address delimiters before
classification: matching brackets, parentheses, braces, angle brackets and
single/double quotes, an IPv4 trailing dot, and an IPv6 zone suffix. It also
examines tokens embedded in additive text after common whitespace, comma,
semicolon, equals, bracket/brace/angle and quote delimiters. Consequently
`[2001:db8::1]`, `198.51.100.1.`, `peer=198.51.100.1` and
`note [2001:db8::1]` are privacy failures as values or keys, including beneath
benign wrappers. CIDR/interface forms are classified safely with IP
interface/network parsing; `198.51.100.1/32` and `2001:db8::1/128` are
privacy failures in additive keys, values and nested additions.

Only the closed V1 fields `local_endpoint`, `published_endpoint`,
`interface_identity_digest` and their validated digest/classification
children, plus the closed safe fields `evidence_digest`, `ownership_state` and
`verification_attempt_id`, are exempt from sensitive key-name matching at
their normative V1 locations. Their values still obey the strict schema.
Using those names as additions elsewhere does not grant an exemption. Frozen
enum strings and `*-v1:<hex>` digests are not locator literals. Recursive
inspection also applies inside objects and arrays owned by an additive field,
preventing a benign wrapper from hiding a sensitive descendant.

The V1 compatibility observer MUST apply these complexity budgets before
projection or schema validation:

| Budget | Inclusive V1 maximum |
|---|---:|
| Nesting depth, with the snapshot root at depth zero | `32` |
| Total visited values/nodes | `4096` |
| Total objects plus arrays | `512` |
| UTF-8 bytes in any individual key or string value | `4096` |
| Aggregate additive-field accounting | `65536` bytes |

Aggregate additive accounting is deterministic: UTF-8 bytes of every additive
key and string, two bytes per additive object/array, decimal digit count plus
sign for integers, four bytes for `null`, five for booleans and 24 for finite
floats. The maximum is inclusive: `65536` is accepted and `65537` is rejected.
Integer digits MUST be counted from their real decimal
representation, not estimated from bit length. If exact conversion itself is
pathological or cannot complete within the implementation's safety limits,
the observer fails closed.

Every key and string, known or additive, MUST encode as valid UTF-8. An
unpaired surrogate or any encoding failure returns `MALFORMED` without an
exception escaping. Values not representable in JSON (`set`, tuple, bytes,
arbitrary objects and equivalents) and non-finite floats are also
`MALFORMED`.

The walk MUST be iterative or otherwise explicitly budgeted. Exceeding any
limit returns typed `MALFORMED` with zero promotion; it MUST NOT throw a
recursion/stack/encoding/conversion exception. Benign additive data within all
five limits remains compatible.

The observer MUST still require every V1 field and apply all V1 invariants,
including bidirectional candidate-ID/logical-identity uniqueness and
lease/state coherence. This deliberate split permits additive forward
evolution without allowing an unreviewed producer to silently widen the
frozen contract. Compatibility does not make the observer actionable: route
and publication code must use the internal typed view described in section 3.

- V1 producer → V1 consumer: fully supported.
- Later additive producer retaining `schema_version: 1` → V1 consumer:
  unknown fields may be ignored; unknown enum values remain non-actionable.
- V1 producer → later consumer: later consumer must preserve V1 semantics.
- Missing V1 field, changed meaning, removed enum, or incompatible type:
  requires a new schema version.
- Any other schema version → V1 consumer: typed `UNSUPPORTED_SCHEMA`,
  no promotion.

The contract has no binary serialization. UTF-8 JSON plus the JSON Schema is
the reproducible artifact; freezing an internal object layout would
incorrectly turn documentation into an ABI.

## 7. Deliberately absent from v9.2

The schema intentionally has no candidate kind or field for `SRFLX_UDP`,
`RDV`, `PREDICTED`, remote direct-connect messages, DCO, Punch, birthday
correlation, DVL, relay selection, QUIC or any v9.3 routing decision. A
producer MUST report such capability outside this contract as
unsupported/not-measured. It MUST NOT encode it through a V1 enum that looks
similar.

No route-selection priority, peer negotiation or remote publication policy is
defined here.

## 8. Goldens and executable RED

The five normative examples are in
[`reachability/goldens`](reachability/goldens):

- `empty.json`
- `candidate.json`
- `verified.json`
- `expired.json`
- `stale.json`

Run:

```text
PYTHONDONTWRITEBYTECODE=1 python tests/test_v92_mx01_direct_candidate_snapshot.py
```

The test validates the schema and every golden, checks closed objects and
redaction, proves candidate/verified separation, exercises additive-field and
unknown-enum compatibility, checks JS-safe integer boundaries, terminal-reason
cardinality, exact direct address classes, absence of raw ports, mapped-lease
zero boundaries, both directions of candidate identity, recursive sensitive
additions, exact complexity boundaries, depth 1500 without exception and
non-native verification denial, and executes a fake contract-only observer.
The normative RED fails if that observer depends on a product mapper class or
a text trace, if a required field is removed, if a future enum can be
promoted, if a benign wrapper can hide a locator, if a budget overflow is not
typed `MALFORMED`, if secret material or invalid Unicode escapes the scanner,
or if the sanitized versus internal-view boundary disappears.
