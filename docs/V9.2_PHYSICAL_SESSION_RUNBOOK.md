## 2. Antes de la sesión (propietario, 15 a 30 minutos)

Elegir una opción. La A es la más corta.

**A. Cable al router Movistar.** Conectar el PC por Ethernet al Movistar
(`192.168.1.1`) y desactivar la Wi-Fi durante la sesión. NAT único. Después:

```powershell
powershell -ExecutionPolicy Bypass -File tools\lab\diagnose_v91_r01_upnp_capacity.ps1
```

Si el censo devuelve `limit_reached` o unas 64 entradas, o si el paso 2 de
§3 devuelve 501: reiniciar el router Movistar (vacía la tabla dinámica UPnP) o
borrar las entradas antiguas desde su web (`Configuración avanzada → UPnP`).
Repetir el censo. Si sigue en 501 tras el reinicio, el router está descartado:
pedir uno prestado para la tarde. `H93-15` no admite T8 como sustituto.

**B. Deco en modo punto de acceso.** App Deco → Más → Avanzado → Modo de
funcionamiento → Punto de acceso. El PC recibe `192.168.1.x` del Movistar y
la Wi-Fi vale. Cambia la red de toda la casa; reversible.

**C. No sirve para H93-15.** Activar UPnP en el Deco (App → Avanzado → UPnP)
mapea solo en el Deco y sigue en doble NAT. Sí vale como caso `V92-C02`
(doble NAT → fallo honesto, sin falso HighID) si sobra tiempo.

En cualquier opción: permitir `C:\tmp\emule-rc2\emule.exe` en el firewall de
Windows (entrante TCP 4662 y UDP 4672); sin eso no hay inbound proof.

## 3. Sesión (una tarde)

Materiales: el zip del candidato y su SHA-256; segundo PC (`H2`) con el mismo
zip; móvil con datos para hotspot y para la prueba de entrada externa;
`pktmon` en ambos; Tailscale solo para administrar, nunca como ruta de datos
(`assert_data_route.ps1` lo rechaza). Directorio de evidencia:
`C:\tmp\g9293-<commit>\`.

1. **Antes.** Censo UPnP del router y guardar el JSON en el directorio.
2. **Sonda.** Mapping de prueba TCP y UDP, con limpieza automática:

```powershell
powershell -ExecutionPolicy Bypass -File tools\lab\probe_v91_r01_upnp.ps1 -Protocol TCP
powershell -ExecutionPolicy Bypass -File tools\lab\probe_v91_r01_upnp.ps1 -Protocol UDP
```

Esperado `MAPPING_PASS` en ambos. Un 501 aquí es parada: volver a §2.

3. **Arrancar el candidato** en `C:\tmp\emule-rc2` con perfil nuevo, mappings
   activados, puertos 4662/4672, web 4711 con token. Comprobar que el estado
   es observable sin logs:

```powershell
powershell -ExecutionPolicy Bypass -File tools\lab\handoff93\reach_probe.ps1 `
  -NodeRole A -Token <token> -Commit <sha> -OutFile C:\tmp\g9293-<sha>\A\reach-baseline.json
```

Esperado `gate_readiness = READY`.

4. **`H93-15`, tres ciclos.** Cada ciclo debe mostrar en `/api/reach/status`
   el plano `ed2k_tcp_v4` pasando por `CANDIDATE → VERIFIED → WITHDRAWN`:

```powershell
powershell -ExecutionPolicy Bypass -File tools\lab\handoff93\run_product_mapper_cycle.ps1 `
  -ExePath C:\tmp\emule-rc2\emule.exe -PackageRoot C:\tmp\emule-rc2 -ConfigRoot C:\tmp\emule-rc2\config `
  -IniPath C:\tmp\emule-rc2\config\preferences.ini `
  -ExpectedExeSha256 4d7eae90c73778a6b147e7798424461889cbea816ce10990389fd1fef775d9f0 `
  -TcpPort 4662 -UdpPort 4672 -WebPort 4711 -ApiToken <token>
```

`VERIFIED` necesita prueba de entrada de la generación vigente: conectar a
un servidor eD2K (HighID = `ServerHighId`) o aceptar una conexión TCP desde
fuera (desde el móvil con datos, `InboundTcpAccept`). `WITHDRAWN` se provoca
borrando el mapping en la web del router o esperando su caducidad; el plan
avisa de reservar la tarde por esas esperas. Guardar cada `reach_probe` y el
censo entre ciclos.

5. **Después de los tres ciclos.** Cerrar eMule de forma natural. Censo:
   cero mappings propios; las entradas ajenas intactas.

6. **`H93-16`, ruta física y cambio de red.** Transferencia de un fichero de
   prueba entre `H1` y `H2` por IPv4 nativo, y el ciclo LAN → hotspot → LAN
   en `H1`:

```powershell
# H1, transferencia en marcha en la LAN
powershell -ExecutionPolicy Bypass -File tools\lab\handoff93\route_change.ps1 -Phase baseline `
  -RunDirectory C:\tmp\g9293-<sha> -TargetProcessId <pid> -ExpectedRemotePort 4662 -RequiredFamily IPv4 -Token <token>
# H1 cambiado al hotspot del móvil
powershell -ExecutionPolicy Bypass -File tools\lab\handoff93\route_change.ps1 -Phase hotspot -RunDirectory C:\tmp\g9293-<sha> -TargetProcessId <pid> -Token <token>
# H1 de vuelta en la LAN
powershell -ExecutionPolicy Bypass -File tools\lab\handoff93\route_change.ps1 -Phase restored -RunDirectory C:\tmp\g9293-<sha> -TargetProcessId <pid> -Token <token>
powershell -ExecutionPolicy Bypass -File tools\lab\handoff93\route_change.ps1 -Summarize -RunDirectory C:\tmp\g9293-<sha>
```

Cada fase se captura una sola vez; repetir una fase es error, no sobrescritura.
La evidencia esperada: datos fuera del overlay, ruta seleccionada registrada y
`topology_generation` incrementada exactamente por el cambio real.

7. **T7 y T3.** La evidencia de los pasos 4 y 6 cubre `92-7.3` (UPnP real:
   crear, readback, propiedad, limpieza) y `92-7.4` (hotspot). Anotarlo en
