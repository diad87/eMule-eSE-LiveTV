## Common header and MAP layout

PCP version is `2`. Request opcodes are `ANNOUNCE=0` and `MAP=1`; responses set
bit `0x80`. All integers are network byte order.

For a MAP request:

| Offset | Size | Meaning |
|---:|---:|---|
| 0 | 1 | version `2` |
| 1 | 1 | opcode `MAP=1` |
| 2 | 2 | reserved, zero |
| 4 | 4 | requested lifetime |
| 8 | 16 | client IP address |
| 24 | 12 | 96-bit mapping nonce |
| 36 | 1 | transport protocol (`6` TCP, `17` UDP) |
| 37 | 3 | reserved, zero |
| 40 | 2 | internal port |
| 42 | 2 | suggested external port |
| 44 | 16 | suggested external address |
| 60… | variable | aligned options |

The base MAP size is 60 bytes and the productive maximum is 1100 bytes.
`PREFER_FAILURE` is option `2` with zero-length data. `PORT_SET` is option
`130`; the frozen example carries size `32`, first internal port `4662` and
parity preservation enabled.

For a response, byte 3 is the result code, bytes 4–7 are the granted lifetime
and bytes 8–11 are the server epoch. The MAP payload begins at byte 24 and must
echo nonce, protocol and internal port. Result codes form the closed native
range `0..13`: success, unsupported version, authorization/malformed/opcode/
option errors, network/resource/protocol/quota failures, inability to provide
the requested external address, address mismatch and excessive remote peers.

## Productive behavior relevant to later cards

`UPnPImplPCP.cpp` generates a nonzero random 96-bit nonce, binds the selected
client interface, accepts responses only from the exact gateway and PCP port,
and delegates nonce/protocol/internal-port validation to the codec. A mapping
success additionally requires nonzero lifetime, nonzero external port and a
usable IPv4-mapped external address. Delete success requires lifetime zero.
TCP and UDP keep independent nonces; a failed UDP mapping rolls back TCP.

The table is implemented in
`tools/lab/nat_gateway/pcp_vectors.js` and checked by
`tools/lab/nat_gateway/test/pcp_vectors.test.js`.
