# eMule eSE 9.3 — Política de modelos GPT

Estado: normativa para ejecución asistida
Versión: 2.0
Modelos disponibles al redactar: `gpt-5.6-sol` y `gpt-5.6-terra`

## 1. Decisión explícita

Sí está definido con qué modelos desarrollar 9.3:

- **Modelo principal:** `gpt-5.6-sol`, razonamiento `high`.
- **Contratos y riesgo crítico:** `gpt-5.6-sol`, `xhigh` o `max`.
- **Implementación acotada tras congelar contrato:** `gpt-5.6-terra`,
  `medium` o `high`.
- **Revisión crítica:** otro contexto independiente de `gpt-5.6-sol`,
  normalmente `xhigh`; `max` para wire, criptografía, Birthday y release.

`gpt-5.6-luna` no aparece entre los modelos seleccionables de esta superficie y
se elimina del routing normativo. Su eventual disponibilidad futura no cambia
automáticamente esta política.

Escribir un modelo en una tarjeta no cambia la sesión. El coordinador debe
crear el contexto correcto y registrar modelo solicitado, modelo real,
razonamiento, fallback y veredicto.

## 2. Perfiles

| Perfil | Modelo y esfuerzo | Uso |
|---|---|---|
| `TERRA-M` | `gpt-5.6-terra`, medium | fixtures, runners, docs y cambios mecánicos |
| `TERRA-H` | `gpt-5.6-terra`, high | codecs congelados, adapters, harness e integración |
| `SOL-H` | `gpt-5.6-sol`, high | arquitectura, estado, identidad y seguridad |
| `SOL-X` | `gpt-5.6-sol`, xhigh | contrato crítico y revisión independiente |
| `SOL-MAX` | `gpt-5.6-sol`, max | wire freeze, crypto, Birthday y promoción |

## 3. Fallback y prohibición de downgrade

```text
TERRA-M/H solicitado:
  Terra disponible -> Terra
  Terra no disponible o trigger crítico -> Sol con esfuerzo igual o mayor

SOL-H/X/MAX solicitado:
  Sol disponible -> Sol
  Sol no disponible -> BLOCKED
```

Nunca se permite `Sol → Terra` para completar una tarjeta clasificada Sol.
Fallback cambia el ejecutor, no el alcance, pruebas ni revisor.

## 4. Flujo mecánico

1. Leer la única tarea `ACTIVE` en `V9.3_EXECUTION_STATE.md`.
2. Resolver perfil por la tabla de este documento.
3. Comprobar dependencias, gate de track y archivos permitidos.
4. Registrar ejecutor y revisor antes de editar.
5. Crear test rojo y evidencia.
6. Implementar el cambio mínimo.
7. Ejecutar `CARD` y regresiones aplicables.
8. Evaluar triggers después de cada fallo o ampliación.
9. Abrir contexto revisor independiente cuando corresponda.
10. Registrar commits, modelos, evidencia y veredicto.
11. Solo entonces cambiar `ACTIVE → PASS`.

## 6. Clasificador

### Terra

Solo cuando:

- el contrato ya está congelado;
- la salida es mecánicamente comprobable;
- no decide autoridad, trust, identidad o política;
- archivos y diff están acotados;
- los tests definen el resultado.

Ejemplos: codecs ya especificados, adapters libnatmap/uTP, fixtures, runners,
matrices, exportadores, UI derivada, framing DVL ya congelado y documentación.

### Sol

Obligatorio para:

- reconciliación tesis/especificación;
- DirectOnly y DCO;
- wire v2/v3, ABI y firmas;
- identidad, autenticación y nominación;
- generación, lifetime, single-winner y exactly-once;
- Witness trust y reservas R;
- Punch2/Punch3 crítico;
- predicción/anti-scan;
- todo diseño Birthday;
- suite criptográfica, transcript y rebinding DVL;
- límites, privacidad y claims estadísticos;
- promoción de cualquier track.

## 9. Checkpoints Sol obligatorios

No pueden cerrarse sin un contexto Sol independiente:

1. ADR tesis/especificación;
2. freeze DirectOnly/DRF;
3. decisión v2/v3 y wire completo;
4. primera proof externa PCP/CGN/IPv6;
5. máquina DCO y primer bloque autenticado;
6. Punch2 exacto sobre mismo socket;
7. primer receipt válido y modelo de trust;
8. primera reserva/Punch3 con captura A/R/B;
9. predicción bajo carga con máximo 17;
10. Birthday B1 antes de B2/B3;
11. freeze criptográfico DVL;
12. rebinding DVL autenticado;
13. primer resultado físico con denominador/CI;
14. Alpha, Beta, RC y Stable Core/A;
15. cualquier promoción Birthday o DVL.

Que Sol implemente no satisface la revisión: el revisor usa otro contexto sin
el razonamiento del autor.

## 11. Revisión

```text
Review only the diff, frozen contracts and supplied evidence.
Assume the implementation is wrong until tests and code prove otherwise.
Check: DirectOnly, route authority, generation, identity, authentication,
nomination, packet/resource bounds, cancellation, single-winner, exactly-once,
no data through R, track isolation, privacy and statistical denominators.
Return APPROVE, REQUEST_CHANGES or BLOCKED with file/line evidence.
Do not implement the fix in this review context.
```

## 12. Métricas de orquestación

Registrar:

- tarjetas por modelo y esfuerzo real;
- fallbacks Terra→Sol;
- triggers y causa;
- intentos hasta verde;
- retrabajo tras revisión;
- defectos escapados;
- revisiones no independientes;
- tiempo de implementación, prueba y revisión por track.

Las proporciones son observacionales, no cuotas.

## 13. Condiciones de autonomía

El agente puede editar, compilar, probar y documentar dentro del worktree
autorizado. Debe detenerse ante:

- gate N0 abierto para cualquier tarjeta distinta de WP93-0;
- freeze 9.2 ausente para cualquier tarjeta distinta de WP93-0; WP93-0 puede
  localizarlo y debe bloquear si demuestra que no existe;
- cambio de router, ISP, firewall, NIC o publicación externa;
- scope adicional;
- S0/S1;
- hardware/cuentas no disponibles;
- contradicción normativa;
- Sol obligatorio no disponible.

## 14. Definition of Done

- [ ] cada tarjeta funcional y QA tiene routing;
- [ ] modelo solicitado, real, esfuerzo y fallback están registrados;
- [ ] cero downgrade;
- [ ] todos los triggers quedan auditados;
- [ ] cada checkpoint crítico tiene revisor independiente;
- [ ] Birthday y DVL usan `SOL-MAX` en sus freezes;
- [ ] ninguna implementación crítica se autoaprueba;
- [ ] indisponibilidad de Terra escala y la de Sol bloquea.
